# Lettr visual system: source map and degrees of freedom

Use [`src/styles/app.css`](../../src/styles/app.css) as the live token source. This document records the current system and how to compose it; if code changes, update the description rather than maintaining a parallel token file.

## Hard brand and system rules

- **Geometry:** `@layer base` sets `border-radius: 0` for every element and pseudo-element. This is intentional. Avoid rounded cards, pills, buttons, and generic soft SaaS chrome, even where old utilities include `rounded-full` (the base rule wins in the current cascade). Preserve square silhouettes unless the owner explicitly changes the brand.
- **Core colors** in `@theme`: background `#f7f1f3`, primary `#ec104b`, surface/ink `#111827`, muted ink `#1f2937`, border `#d1d5db`. White and dark surface panels provide contrast. Module colors in the same file are for changelog categories, not a new marketing palette.
- **Fonts:** heading “Zalando Sans SemiExpanded” (always weight 400); body “Manrope”; code “DM Mono” — loaded from Google Fonts in [`src/app.html`](../../src/app.html). Accent “Redaction” (smooth, italic) and “Redaction 20”, the only pixelated cut, self-hosted from `static/fonts/`.
- **Type scale and roles:** semantic roles `type-display`, `type-h1` … `type-h6`, `type-lead`, `type-label`, `type-accent` and body tokens (`text-body`, `text-prose`, `text-body-sm`, `text-caption` …). See [`design-system.md`](design-system.md) for the table and rules, and `/design-system/` on the dev server for the specimen.
- **Logo:** [`static/logo.svg`](../../static/logo.svg) and favicon assets are the actual marks. Use actual assets, not a generated substitute.

## Current implementation conventions (inspect before reusing)

- **Shell/container:** [`+layout.svelte`](../../src/routes/+layout.svelte) wraps the main page in `max-w-[1200px]` (`max-w-page`), `px-6`, subtle `border-x`, with a fixed top [`Navbar.svelte`](../../src/lib/components/Navbar.svelte). `narrow` removes side borders below 500px; declared in `app.css`. The 1200px frame is a strong current convention, but a future concept can reconsider how sections use or break out of it without changing brand tokens.
- **Spacing:** Tailwind's 4px unit on an 8px grid, plus `section-y` / `section-y-sm` / `section-y-lg`, `stack-section`, container tokens (`max-w-page`, `max-w-wide`, `max-w-content`, `max-w-measure`, `max-w-article`) and three shadows (`shadow-panel`, `shadow-float`, `shadow-offset`). Rules in [`design-system.md`](design-system.md).
- **Borders/surfaces:** thin `border-border/30` to `/60`, dividers, white panels, blush page background, occasional dark `bg-surface` section. The branch's dark [`DeveloperPath.svelte`](../../src/lib/components/home/DeveloperPath.svelte) shows deliberate contrast. Use borders to clarify structure, not to turn every idea into a card.
- **Buttons:** marketing [`Button.svelte`](../../src/lib/components/Button.svelte) is the one component for actions: sizes `lg` (hero and section CTAs), `md` (cards and forms), `sm` (navigation, compact rows); variants primary, secondary, outline, ink, green, ghost; focus-visible, disabled and loading states. [`ui/button/button.svelte`](../../src/lib/components/ui/button/button.svelte) remains for booking-form controls. Form controls in [`ui/input/input.svelte`](../../src/lib/components/ui/input/input.svelte) use white, a border, and visible pink focus ring. [`ui/card/card.svelte`](../../src/lib/components/ui/card/card.svelte) is a lightweight bordered surface; its availability is not a reason to use cards everywhere.
- **Icons and UI graphics:** components mostly import `phosphor-svelte`; `@lucide/svelte` also appears in the dependency set. Actual brand/integration SVGs are under [`static/images`](../../static/images). Email-editor and campaign graphics are mostly Svelte-built demonstrations in [`EditorPreview.svelte`](../../src/lib/components/EditorPreview.svelte), [`CampaignEditorPreview.svelte`](../../src/lib/components/CampaignEditorPreview.svelte), and [`TeamFeatures.svelte`](../../src/lib/components/TeamFeatures.svelte). They are conceptual previews, not a canonical screenshot library. The branch hero uses procedural, dithered envelopes in [`DitherHero.svelte`](../../src/lib/components/home/DitherHero.svelte); the extra rose tint is local to that visual, not a global color token. The two PNGs under `static/images/blog/introducing-audiences-and-campaigns/` are existing product-story assets.
- **Shadows:** selective custom shadows appear on product previews, hover states, pricing emphasis, and the navbar dropdown; there is no global shadow token scale. Avoid adding depth as default decoration.
- **Responsive:** custom `narrow` is `max-width: 500px`; Tailwind `sm`, `md`, and `lg` utilities are used throughout. The nav changes at `md`; mobile product previews often scroll/snap or swap layout; test at narrow, tablet, and desktop widths. See [`TeamFeatures.svelte`](../../src/lib/components/TeamFeatures.svelte) for a mobile tab/scroll example.
- **Motion:** [`Hero.svelte`](../../src/lib/components/Hero.svelte) uses CSS entrance motion with a reduced-motion override. Sections do not fade in on scroll: content is always visible (scroll reveals were removed because they flashed). Subpage heroes are static. Svelte transitions and small hover changes appear in components; there is no animation library. [`SplineFooter.svelte`](../../src/lib/components/SplineFooter.svelte) loads a Spline scene near the footer only on sufficiently wide screens without reduced motion. Motion should reveal a relationship or transition, maintain a useful static state, and honor reduced motion.

## Flexible composition patterns

Retain the palette, type identity, square geometry, and product truth while varying section width, scale, alignment, sequence, contrast, and interaction. A single large line of type can outweigh many labels. A narrow product detail may communicate the workflow better than a full tiny dashboard. Split a complex story across a toggle or a step sequence. Allow a section to have a strong light/dark change, an asymmetrical focal object, or a controlled frame break when the message warrants it. These are options, not templates to repeat. The homepage's current many-card and repeated heading/paragraph structure is existing implementation, not a system requirement.
